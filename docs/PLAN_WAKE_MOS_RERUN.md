## 1. 问题分析

### 1.1 长时间对话中断 / 需重新唤醒

**现象**：跑 3～4 条后助手退出聆听，后续语料无人应答，整案 GUI/ASR 失败。

**原因（产品侧）**：助手会话超时或未保持唤醒；PC 侧每案虽已播唤醒词，但：

1. 唤醒 TTS **成功率约 70～80%**，失败时当前实现**不感知**，仍继续播步骤；
2. 边沿 edge 语料偶发「误唤醒/抢焦点」，与「唤醒失败」不同，需分开记；
3. 无「唤醒结果」维度，报表只能看到下游 GUI 失败，难归因。

**你提的措施映射**：

| # | 措施 | 方案态度 |
|---|------|----------|
| 1 | 每案唤醒 + 优化唤醒语音，避免整案失败 | **做**：专用唤醒音频策略 + 失败重试 |
| 2 | 全量 edge-tts，过程中可能唤醒 | **保持** edge；误唤醒只记日志/轻量标记，不强杀 |
| 3 | 界面无变化且无对话气泡 → 唤醒失败 | **做**：轻量 wake 判定（见下） |
| 4 | 单用例 / 全部失败重跑 | **做**：任务 API + UI |

### 1.2 便携屏黑屏停止播报

**现象**：外接/便携屏进黑屏后，本机 TTS 播报中断或听不到。

**可能链路**（需在 PC1 验证哪一种）：

- A. Windows 因「显示器关闭」触发休眠/音频设备切换，**ffplay/播放进程停或路由到错误设备**；
- B. 仅屏幕灭，播放仍在，但人耳/设备麦侧表现为「停了」；
- C. 设备侧熄屏导致助手不拾音（与 PC 播报无关）。

**方案**：端侧跑测前/每案前 **保活**（防系统睡）+ 可选 **ADB 亮屏**；播放侧固定输出设备（若已配置）。不假设改 Windows 电源策略 alone 就够。

### 1.3 MOS 失败、录屏无声音

**已确认环境因素**：ICPM 拦截 `scrcpy` → 内录失败或无有效音轨；`mos.source=video` 时无音轨则该句 MOS 失败/N/A，**不会**自动改主机麦。

即使 scrcpy 放行后，仍可能：音频编码器失败、静音策略、仅视频轨。

**方案分层**：先让「无音轨」在报告里归因清晰；ICPM 放行后 MOS 才稳定；可选 `auto` 在无音轨时提示改 `host_mic`（你此前定过默认 video、不中途静默降级——保持，只把诊断做清楚）。

## 2. 推荐方案（确认后开发）

### P1 — 唤醒可靠化 + 唤醒失败标记

**目标**：唤醒失败可检测、可重试；失败时用例标记 `wake_failed`，避免「假 GUI 失败」污染。

1. **唤醒播报策略**（可配）  
   - 保留每案一次唤醒；新增 `wake_max_attempts`（建议默认 2～3）。  
   - 候选音频：预合成库中同文案多条，或轻微调速/响度变体（仍 edge）；优先用库命中。  
   - 每次尝试：播 → `wake_wait_sec` → **判定** → 失败则再试。

2. **唤醒成功/失败判定**（你提的第 3 点）  
   - 时机：唤醒词播完后短窗（可复用/略短于 ASR 窗，如 2～4s）。  
   - 信号（需同时偏「失败」才判失败，避免误杀）：  
     - 画面相对唤醒前基线 **无明显变化**（可复用时延类差分，忽略底部条可选）；  
     - **且** 底部/上方区域 **无对话气泡**（OCR/VL 轻量，或底部带像素变化启发式；首期可用 VL 一句专用 prompt，与 GUI 评判分离）。  
   - 结果写入 `timeline.wake`：`status=ok|failed`、`attempts`、截帧路径。  
   - **策略（请你拍板其一）**：  
     - **A（推荐）**：唤醒最终失败 → 用例 `device` 标 `wake_failed`，**跳过本条后续语料与 GUI/ASR/MOS**，直接下一条（省时间）；  
     - **B**：仍跑完语料，但汇总里强制记 wake_failed，GUI 结果标「可能未唤醒」。

3. **报表**  
   - summary / 任务列表增加唤醒失败计数；与 GUI fail 分开。

### P2 — 任务：单用例重跑 + 重跑全部失败

**目标**：不必整集重开。

1. API（示意）  
   - `POST /api/runs/:id/rerun` body：`{ mode: "case"|"failed", case_id?: string, params?: overrides }`  
   - 新建子任务或同 job 追加 results（**推荐新建 job，关联 `parent_job_id`**，避免覆盖历史）。  
2. UI  
   - 任务详情：每条失败行「重新执行」；顶部「重跑全部失败」。  
   - 运行中任务禁用重跑。  
3. 范围：重跑走完整 `capture_one_case`（含唤醒/录屏）；预置缓存仍复用。

### P3 — 熄屏 / 停播防护

1. **跑测会话级**（PC1）  
   - 文档 + 可选脚本提示：电源计划「使计算机进入睡眠=从不」；外接屏可「关闭显示器」但勿睡。  
   - 代码：任务开始时尝试 `powercfg`/`SetThreadExecutionState` 类保活（Windows），结束时恢复。  

2. **每案前设备亮屏**（ADB）  
   - `input keyevent KEYCODE_WAKEUP`（+ 必要时轻微唤醒滑动，可配开关 `run.ensure_screen_on`）。  

3. **播报**  
   - 若播放异常退出，日志明确 `play_interrupted`；不静默当成功。

### P4 — MOS / 无声音轨

1. **归因**  
   - 无音轨时 MOS 结果写清：`no_audio_track` / `scrcpy_blocked`（若启动失败），UI 提示检查 ICPM + scrcpy 试录。  
2. **环境**  
   - 继续依赖 ICPM 放行 scrcpy（此前已确认命令行也会弹）。  
3. **配置**  
   - 保持默认 `mos.source=video`；控制台文案注明：无声请先修 scrcpy，或临时改 `host_mic`。  
4. **不做**：在 `source=video` 时偷偷改录主机麦（与既有决策一致）。
